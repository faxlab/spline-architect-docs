---
title: Adopt the baked-first workflow
description: Use Baked generation for editor production, understand automatic unbake, and reserve Runtime for gameplay generation.
---

Spline Architect v6 is designed around **Baked** generation for editor-authored production work. Baked mode does not mean the actor must stay permanently baked while you design: it establishes that the intended production output is persistent editor geometry.

![Baked-first authoring lifecycle](/img/diagrams/baking-lifecycle.svg)

## The loop

1. Keep Wall, Building, Curve, and Streets output in **Baked** generation mode while authoring.
2. Edit splines, presets, custom pieces, booleans, and seeds. The actor generates an editable preview.
3. Select a root or any member of a connected stack and use **Bake Connected**.
4. If an authored input changes, Spline Architect automatically unbakes the affected output rather than leaving stale baked geometry.
5. Inspect the regenerated result, then choose **Rebake Connected** explicitly.

This keeps production geometry deliberate: changes are visible immediately, but rebaking is a conscious checkpoint.

## Choose a bake method

| Method | Best for | Trade-off |
| --- | --- | --- |
| **Components** | Pieces that need individual transform or component editing after bake. | Highest component and draw-call cost. |
| **Instanced** | Repeated identical pieces with good draw-call performance and instance custom data. | Individual instances are not ordinary editable mesh components. |
| **Hierarchical Instanced** | Large scenes that benefit from per-instance LOD and culling. | More hierarchy overhead; individual instance editing is limited. |

Use **Static** mobility unless output must move. Stationary and Movable reduce the assumptions Unreal can make for lighting and rendering.

## Runtime generation

Use **Runtime** only when gameplay must construct or alter the actor during play. Runtime output is transient and regenerated by the running game; no persistent editor assets are created. Confirm the gameplay cost, collision requirements, replication plan, and platform budget before choosing it for a large environment.

Continue with [Baking and rebaking](/production/baking) for connected commands, prebaked corners, save behavior, registry diagnostics, and failure recovery.
